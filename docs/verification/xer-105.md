## Browser checks

The local Chromium in-app browser inspected the actual platform fonts through its DOM/CSS diagnostics. It reported `RalewayRoman-SemiBold`, `NotoSans-Regular`, `CascadiaCode-Regular` and `CascadiaCode-Italic` for the primary probes. With primary font requests blocked, body and Danish text used `OpenSans-Regular`, code and comments used `FiraCodeRoman-Regular`, and headings used macOS system text. The page remained readable without a manual fallback selection.

Cascadia ligature and cursive screenshots were checked visually against the disabled settings. The cursive and ligature controls are independent. Fira has no supplied italic face; `font-synthesis: none` leaves its comments upright. The named CSS styleset is defined only for Cascadia, so its `ss01` preference does not enable Fira's unrelated feature.

Standard slanted italic is the default for comments and keywords. Handwritten forms are off on a fresh page load. Browser inspection confirms normal alternates with the real italic face, while ordinary code remains upright. The explicitly labelled Handwritten italic control enables the optional styleset and returns to standard italic when unchecked. This default and the updated distribution passed a fresh `mise run ci` run with all 101 tests. The current visual sample is `dist/verification/xer-105-standard-italic.png`.

The 200 percent check uses root text enlargement in the specimen, not a claim about the host application's native zoom control. All nine combinations of three colour modes and primary/named-fallback/system fonts passed the 390px reflow check. Long paragraphs and paths reflow without losing content. All controls retain labels and focus outlines. Release testing in the latest two stable versions of Chrome, Edge, Firefox and Safari remains XER-119 work.

## Repeatable verification

Run the following from the repository root:

```sh
mise run fonts:validate
mise run ci
mise run test:clean
```

`mise run ci` and `mise run test:clean` both passed, including a frozen Bun install in a source-only temporary copy. The 101 Python tests include 13 font checks covering pinned assets/licences, corrupt bytes, malformed WOFF2 headers, stale inspection, unsupported weights, missing styles, unsafe paths, Danish probe retention, source-file protection and deterministic output. Svelte reported zero errors and warnings. All 360 tokens per mode, 412 contrast pairs, 102 platform values and 75 local documentation links passed. Ordinary CI uses saved inspection plus hashes; rerunning native Fontconfig inspection is the separate asset-update procedure.

The independent archive consumer verifies that the exported stylesheet resolves, that all nine relative font URLs exist, and that the font and licence hashes match the manifest. Svelte and Storybook builds include the stylesheet and font assets. Artifact checks compare repeated typography/font builds, specimen/package copies and local document links. All verification is local; no remote CI or native editor/terminal result is implied.

Generated browser evidence is saved under `dist/verification/`: `xer-105-typography.png`, `xer-105-features-on.png`, `xer-105-features-off.png` and `xer-105-reflow.json`. The Svelte static example also uses relative asset paths, so it opens correctly beneath `dist/reference/`. Browser font inspection confirms the bundled Raleway and Noto Sans faces in that built example and the static Storybook story. Keyboard Tab moves from Mode to Fonts with a visible 2px solid focus outline.
