# XER-140 Zed adapter verification

Delivery branch: `codex/xer-140-resume`. Rebuilt on 6 November 2026 at the owner's request because the previous XER-133/XER-140 implementation is on another computer. This delivery is independently verified; it does not reproduce or certify the unavailable earlier commit.

## Automated checks

The declarative adapter foundation validates source roles, required mappings, target metadata, modes and fallback declarations before serialization. The WezTerm reference remains byte-identical to the existing export for Fjord and Fern. Both adapters and their upstream schema/licence files are included in source candidate archives so an extracted candidate can rebuild them.

The Zed adapter emits Night, Day and Aurora against the pinned official v0.2.0 schema. The coverage report identifies every mapped and unsupported semantic colour. Schema validation rejects unknown emitted fields, invalid types and invalid colours. Focused tests cover deterministic generation, Fern reuse, source protection and the retained-text highlight failure.

Zed shares selection/search fills between the editor and terminal. The adapter checks retained text against emitted 8-bit HEX fills and records every substitution. Aurora uses a documented terminal hint-colour fallback to keep its selection visible. ANSI black in dark modes is an intentional palette slot rather than ordinary text and is explicitly excluded from that text claim. Runtime APCA correction, unfocused selection opacity and terminal SGR DIM compositing have separate limits; raw HEX checks do not prove every rendered pixel. See [the mapping and limitations](../../adapters/zed/README.md#mapping-and-retained-text).

The generated family maps 171 targets from 58 semantic colours, with 23 explicit unsupported colours and zero unmapped colours. The final report checks editor/base, active-line, terminal, highlight and diff/status surfaces:

| Mode | Emitted contrast comparisons | Lowest ratio |
| --- | --- | --- |
| Night | 480 | 4.522057:1 |
| Day | 486 | 4.501808:1 |
| Aurora | 480 | 4.500657:1 |

All 1,446 comparisons pass their 4.5:1 threshold. Gutter line numbers are checked on editor surfaces, outside the selected text region. The negative diff regression proves that a `diff-add-bg → search-match` override can pass the shared contrast contract while failing retained syntax in Zed; generation rejects it before writing output.

**PASS:** `mise run ci` completed after the Aurora correction with 155 Python tests, Svelte/TypeScript checking, reference and Storybook builds, deliberate source/consumer/Storybook type-error probes, deterministic token/adapter artifacts and 132 local links. Eleven focused Zed tests cover the highlight and diff regressions, explicit Aurora substitutions and unchanged syntax. Independent static review found and resolved relative `--root` handling and the macOS install path, then found no remaining code defects in the Aurora correction. The combined CI log is in `dist/verification/xer-140-ci.log`.

**PASS:** `mise run test:candidate` then verified the archive, installed its locked dependencies and rebuilt its extracted sources through full CI with all 155 tests and 132 local links. Both adapters regenerated deterministically from those sources. The log is in `dist/verification/xer-140-candidate.log`. This verifies the source bundle; it does not publish or accept a new release.

Host: macOS `26.7.1`, build `25G241`. The separately inspected on-disk bundle reported `1.26.2`; that metadata was not used to identify the running application. The original task's `1.25.3` target and the on-disk `1.26.2` version have no native support claim from this session.

A disposable profile could not open alongside the existing Zed process after three launch routes. The owner then explicitly approved using the running application and restoring its settings. A temporary `fjord-xer-140-verification.json` theme file was installed in the previously empty user themes directory. A separate fixture workspace under `dist/verification/zed-workspace/` supplied a disposable Git repository with added, modified and deleted files. Existing fonts and language servers were reused.

**PASS, all three modes:** JSON and shell syntax; TypeScript comments, keywords, numbers and strings; readable line numbers and cursor; the intentional type-error underline and inline message; native side-by-side Git diff with added/deleted signs and text; editor selection and search; all sixteen labelled ANSI slots and selected terminal text. Search navigation moved from match `3/3` to `1/3`. These are bounded fixture checks, not a complete accessibility audit or coverage of arbitrary terminal programs.

The owner found the first Aurora selection hard to see. Its fill (`#031111`) was almost the same as the base (`#080e16`). The Aurora-only adapter fallback now emits the existing `ink-subtle` (`#92a1ae`) for ten terminal bright-black/dim targets and retains the source selection teal (`#093b3b`). The fill/base ratio changes from 1.00684:1 to 1.56754:1; this is a visibility comparison, not a WCAG pass threshold. Search uses the measured safe fill `#483318`. Shared tokens, syntax and Night/Day visuals are unchanged. The stronger editor selection, search and terminal selection were rechecked natively; the owner confirmed the updated selection was **clear enough**.

Screenshots are in `dist/verification/zed-native/`: `about.jpg`; Night/Day/Aurora `selection`, `search`, `json`, `shell`, `diff`, `terminal` and `terminal-selection` JPEGs; Aurora `selection-before` and `selection-after`; and `restored.jpg`. A copy is attached to [XER-140](https://linear.app/xerrion/issue/XER-140/byg-zed-temaer-fra-fjords-faelles-tokenkilde) as **Native Zed 1.27.0 verification**.

**PASS restoration:** the original settings bytes were restored, including System mode, Catppuccin Latte for light and Catppuccin Mocha for dark. Before/after settings SHA-256 values match. The temporary theme file was removed; the fixture window was closed; the previous workspace and Catppuccin appearance were observed again.
