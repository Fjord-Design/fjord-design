## Resolved Storybook failure

`@storybook/svelte-vite` and its Storybook types load shared declarations that reference the React renderer. Current stable `@storybook/react`, `@types/react` and `@types/react-dom` provide those declarations. Before the patch, the published file `@storybook/react/dist/chunk-ojHmM-yX.d.ts` produced four errors:

| Published location | Diagnostic |
| --- | --- |
| Line 1026 | TS2578: unused `@ts-expect-error` directive |
| Line 1026 | TS2344: `MetaInput` does not satisfy the required component annotation constraint |
| Line 1072 | TS2578: unused `@ts-expect-error` directive |
| Line 1072 | TS2344: `TInput` does not satisfy the required story annotation constraint |

The published declaration places each error directive inline. TypeScript 6.0.3 reproduced the same four errors, so changing the checker did not fix the declaration problem. The initial clean source-copy check also reproduced it with TypeScript 7.0.2.

The [Bun patch](../../patches/README.md) composes `ReactMeta` with its own input and story overloads, and passes mocked argument types into `ReactStory` through a defaulted generic parameter. It removes the two obsolete inline directives. The regression suite verifies required/default args, callback mocks, render overloads and typed results, plus five invalid cases. The patch modifies no runtime JavaScript and retains Storybook's upstream MIT notice.

Verify the installed correction from the repository root:

```sh
mise run setup
mise run reference:check
mise run test:storybook-types
mise run test:clean
```

`mise run ci` and `mise run test:clean` both pass with Storybook 10.6.3 and the patch. Recheck the registry before upgrading. Remove the patch when a later stable release passes the same regression suite without it.
