# Migrate the local MVP to version 1.0

The accepted MVP is `0.1.0`. Its Svelte reference progressed independently to `0.8.3`. The complete local release uses Svelte `1.0.0`, accepted by the owner on 8 November 2026 with [recorded limits](verification/m3-m4.md). Token contract `0.3.0`, token names, alias precedence and all 23 MVP component exports remain unchanged. There are 43 additive component exports. ThemeScope and Icon remain supporting primitives outside the 66 source names.

1. Keep the previous local package/archive and application lockfile. Build and verify the new [local distribution](distribution.md), then install its versioned Svelte package in a feature branch.
2. Retain typography, foundations, semantics and the existing component CSS imports. Add `@fjord/svelte/complete-components.css` when using new components. Add Work/Gaming CSS only when selecting those identities. Source-workspace imports and built-package exports have different paths; consumers use the package exports.
3. Keep existing ThemeScope mode and identity values. Night remains the default; System stays explicit and application persistence stays application owned. Reset new variants with `identity="fjord"`.
4. Consult the [exact component matrix](components/matrix.json) and each family contract for IDs, localized labels, bindings and callbacks. NativeSelect remains available alongside custom Select/Combobox. Required custom Select rejects missing or disabled selections during form validation. Combobox clears the previous selection when edited and keeps active keyboard options visible. Slider normalizes supplied values to its bounds and step. The exact numeric field retains intermediate digits until the edit is committed.
5. Compose application data flows explicitly: DataTable handles resident rows, Pagination receives total/page/pageSize, Questionnaire calls an application submission handler, and attachment/message components do not perform network requests or persist history. Test the new combined catalogue workspace before adopting similar flows.
6. Build native bundles into a new directory. Apply only the relevant colourscheme/extension using its README. Preserve fonts, shell settings and unrelated application configuration. Neovim and new editor variants retain the [support limits](support-matrix.md); generated format validation does not establish native compatibility.

Run your application's type/build checks and the keyboard, focus, form, dark/light, enlarged-text and assistive-technology flows it uses. To roll back, restore the previous package and lockfile and select the previous native theme/configuration; remove only Fjord files added during installation. The new release does not modify application globals automatically.
