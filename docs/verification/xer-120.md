# XER-120 MVP candidate

This is a local candidate for MVP `0.1.0`, not an accepted release. The token contract is `0.3.0`; the Svelte package has its own version in `svelte/package.json`.

Run `mise run release:prepare` to build the token exports, Svelte reference, Storybook and contrast report and assemble `dist/release/fjord-mvp-0.1.0-candidate.zip`. The archive contains those outputs, the source project, component and theme documentation, brand assets, Fern source example, MIT licence and changelog. Its `manifest.json` records SHA-256 hashes of the included files. The archive is local and the task does not publish it.

The source repository's [theme guide](../theme-guide.md) explains clean-checkout setup, consumption and adaptation. The [component inventory](../components/inventory.md) lists the 23 MVP components. Fonts and icons in the Svelte output include their original notices. The archive also collects installed dependency metadata and supplied licence and notice files recursively under `third-party-notices/`, including `ThirdPartyNoticeText.txt` and nested vendor notices. Additional exact-version upstream notices, including Oxc's third-party notices, are retained under `licenses/upstream/`. The is-reference and locate-character publication commits contain MIT declarations but no separate licence text; their original README files and that limitation are preserved. The inventory retains build-dependency notices as well as those for catalogue dependencies.

Run `mise run test:candidate` to prepare the archive, verify exact manifest membership, every file's checksum and the Svelte/token version declarations, then extract it into an isolated temporary directory and run the locked dependency installation and full CI there. The extracted archive has no `dist/` build cache: the check regenerates outputs from its own sources. This verifies the delivered source bundle, separately from `mise run test:clean`, which starts from the checkout. Checksums detect changed files but do not authenticate the publisher.

The first archive build exposed a missing `.github/workflows/validate.yml`, required by the source formatting task. The candidate now includes that file, with regression coverage for its presence.

After that fix, the isolated archive check passed on 27 October 2026: frozen installation, token validation, component semantics, TypeScript 7 source and consumer probes, Svelte/Vite/Storybook builds, generated-output checks and local documentation links all completed from the extracted sources. The new archive verifier also rejects corrupted or missing members, stale version declarations, duplicate paths and symlinks before extraction.
