Delivery branch: `codex/xer-134-vscode-themes`, based on merged PR #1 (`91ee77e`). [ADR 0001](../decisions/0001-platform-boundaries.md) places VS Code after Zed. Native verification on 6 November 2026 covers the running VS Code `1.145.0` Universal build, arm64, commit `a717861c07586a53d83b80d742cd3f59b20a6273`, on macOS `26.7.1` build `25G241` (Darwin `25.6.0`). About also reports Electron `43.8.3` and Chromium `150.0.7871.250`.

## Generated themes and installation package

`mise run adapters:vscode` generates Night, Day and Aurora from the shared semantic tokens and builds a local `dist/release/fjord-themes-0.1.0.vsix`. Workbench colours, TextMate scopes and semantic tokens belong to the adapter; shared token sources and platform-independent core remain separate. The [adapter guide](../../adapters/vscode/README.md) records mapping and runtime limits.

The deterministic VSIX contains only the extension manifest, three generated themes, README and MIT licence, with the required VSIX XML metadata. It contains no executable extension code or dependencies. The local `fjord` publisher identifier does not claim Marketplace ownership. The format follows [Microsoft's extension manifest contract](https://code.visualstudio.com/api/references/extension-manifest) and the [official vsce packaging implementation](https://github.com/microsoft/vscode-vsce/blob/v4.0.0/src/package.ts). Packaging is performed with the Python standard library; no additional packaging dependency or Marketplace account is required.

## Native checks

**PASS installation:** the installed VS Code CLI accepted `fjord-themes-0.1.0.vsix` in isolated user-data/extension directories and listed `fjord.fjord-themes@0.1.0`. The UI controller could not select that separate application process, so visual inspection used a temporary named profile in the existing process. Only that profile's settings were written. A disposable Git workspace under `dist/verification/vscode/workspace/` supplied the bounded fixtures.

**PASS, all three modes:** native theme selection; TypeScript comments, keywords, strings and numbers; the deliberate type-error underline and readable `ts(2322)` message; JSON property keys and values; shell syntax; visible cursor/line numbers; editor selection and search; native side-by-side Git changes with added/deleted signs and A/M/D labels; all sixteen labelled ANSI slots and readable selected terminal text. Search navigation wrapped from `2 of 2` to `1 of 2` in each mode. A Night token-inspector screenshot confirms a semantic `function` token and its theme colour `#83d3be` on `#111920`. Aurora terminal find reports `1 of 16` matches with visible independent borders.

The test profile used the already installed Cascadia-derived `CaskaydiaCove Nerd Font` at 16px with ligatures enabled; native arrows/comparisons and italic comments were visible. No fonts or language servers were installed. Terminal minimum-contrast adjustment was set to `1` in the test profile to inspect the supplied ANSI palette directly. Night/Aurora ANSI black remains an intentional dark palette slot; these checks do not claim ordinary readable black text on a dark base. Runtime dimming, truecolour, reverse video, user overrides and arbitrary terminal programs remain outside the measured raw-colour claim.

The installed theme files matched the final generated files byte-for-byte before cleanup. Both temporary theme installations were uninstalled, the named profile was deleted, the separate test process was stopped and the fixture window was closed. The original workspace was observed again. **PASS preservation:** the normal `settings.json` and default extension registry hashes match their values before testing. The generator and package contain no settings-writing code.

Native screenshots, exact metadata, scenario results and SHA-256 values are bundled in `dist/verification/xer-134-native-2026-11-06.zip`. The archive includes only fixture screenshots and a verification manifest; it excludes normal settings, profile data, application logs and unrelated project views. A copy is attached to XER-134.

These are bounded fixture checks, not a complete accessibility audit. Other operating systems, editor versions, high-contrast modes, third-party grammars and extension-specific semantic token types remain untested.
