## Automated checks

Use `mise run ci` and `mise run test:clean`. Semantic tests cover all identities/modes and pairs, incomplete state/mode sources, disabled-role misuse, weakened or bypassed thresholds, invalid token references, transparent checked surfaces, deterministic output and source overwrite protection. Mode tests cover explicit choices, SSR defaults, system updates and listener cleanup. The Svelte server-rendering fixture contains no client script.

Both workflows passed with 120 Python tests, zero Svelte errors/warnings, source and independent-consumer TypeScript probes, 400 tokens per mode, 430 contrast pairs per identity, 102 platform values and 87 local documentation links. The Fern report checks another 430 pairs across its modes, for 860 identity/mode pair checks in the semantic delivery. No new library dependency was installed.

## Rendered checks

The native sample is `dist/semantics.html`; the Svelte story is Foundations/Semantic modes. Browser evidence is saved under `dist/verification/xer-107-*`. Checks cover explicit/system mode priority, live OS-preference changes through emulation, identity changes with stable component structure, nested scopes, keyboard/loading behaviour, selection, error association, overlay dismissal, narrow reflow and forced colours.

The server-only fixture `dist/verification/xer-107-system-ssr.html` exercises scoped System CSS without a client script. These local Chromium checks and system-preference emulations do not establish the complete XER-119 release matrix or native assistive-technology coverage.

## Observed browser results

Night remained dark with an emulated light OS. Selecting System resolved to Day and then followed an emulated change to dark as Night. Explicit Day remained Day under a dark OS. The Svelte story reproduced this behaviour while its nested explicit Day scope retained its own mode and Fjord identity. Changing the outer identity to Fern changed the primary action to green while preserving the inner blue Day action and the component structure.

A pending save retained focus and busy semantics during a system change. A second Enter did not increase its request count. Completing the demonstration restored focus to the original action. The invalid field retained `aria-invalid` and its associated error. The native overlay focused Close overlay, stayed opaque, and returned focus to its opener after Escape.

All six identity/mode combinations passed at a measured 390px viewport and 200 percent text: body text was 30px and document client/scroll widths were both 375px. Forced-colour/reduced-motion emulation preserved borders, distinct disabled/help roles and static feedback. Temporary preferences and viewport overrides were reset.

The server fixture had zero script elements. In light mode its Fern action immediately used RGB(50,102,53) with a light foreground; in dark mode it used RGB(160,203,160) with a dark foreground. Only shadow transitions remain, so theme colours do not interpolate through low-contrast combinations. Computed primary foreground/background pairs were checked across all six interactive modes and the two script-free modes.

Evidence files include `xer-107-semantics.png`, `xer-107-fern-day.png`, `xer-107-svelte-scopes.png`, `xer-107-forced-colors.png` and `xer-107-measurements.json` under `dist/verification/`.
